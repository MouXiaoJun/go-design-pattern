# 原型模式 Prototype Design Pattern

**分类：**创建型。利用已有对象进行复制的方式来创建新对象，达到节省创建时间的目的。

**定义：**当对象的创建成本比较大、且同类对象之间差别不大时，不重新走一遍复杂创建流程，而是复制一个已有对象（原型）再微调。

**使用场景：**

- 对象创建成本比较大
  - 对象数据需要经过复杂的计算、排序、hash 等
  - 需要从 RPC、网络、数据库等非常慢的 IO 中获取
- 同一个类的不同对象之间差别不大

## 实现方法

1. 给对象提供**复制方法**（`Clone()`）
2. **深拷贝**：复制后与原对象完全独立，改克隆体不影响原型
3. **浅拷贝**：只复制引用，嵌套对象仍共享（拷贝成本低，但要小心共享状态被误改）
4. Go 里没有内建 clone，需要自己实现

## 是否使用

- **何时用**：创建成本高（慢 IO、重计算）且批量需要相似对象时
- **慎用**：对象简单、创建便宜时，直接 `new` 更清晰；深拷贝做不好（循环引用、未导出字段）会埋 bug
- Go 里很多场景用「值类型 + 直接赋值」天然实现浅拷贝，深拷贝才需要显式方法

## Go 落地要点

- **浅拷贝**：结构体直接赋值就是浅拷贝（嵌套指针仍共享）
- **深拷贝**：常用 `encoding/json` 序列化再反序列化，但**只能拷贝导出字段**（未导出字段会被忽略，见 `prototype.go` 里踩过的坑）；字段多、性能敏感时手动逐字段复制更可靠
- 更专业的深拷贝可以看 `github.com/mohae/deepcopy` 这类库，但学习阶段手写更懂原理

## 相关模式

- **工厂模式**：创建新对象；原型是「复制已有对象」的另一种创建方式
- **建造者模式**：分步构建复杂对象；原型适合「构建流程本身昂贵」的场景
