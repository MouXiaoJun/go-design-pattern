# 备忘录模式 Memento Design Pattern

**分类：** 行为型模式，在不暴露对象内部结构的前提下，保存并恢复对象某个时刻的状态（快照）。

**定义：**

备忘录模式解决的是「状态快照与回滚」问题：对象运行到一半需要能回到之前的某个状态（撤销、存档、断点恢复），但直接把内部字段暴露给外部去保存会破坏封装。备忘录模式把「保存状态」和「恢复状态」的责任分到三个角色上：发起者（Originator）负责产出和消费快照，备忘录（Memento）只承载状态数据，负责人（Caretaker）负责保存快照序列而不关心快照内部结构。

在 Go 中落地很直接：备忘录就是一个只读的结构体，字段小写、对外只暴露必要的读取方法；发起者实现 `Save()` 返回快照、`Restore()` 用快照覆盖当前状态；负责人维护一个快照切片或栈。Go 没有访问修饰符，靠小写字段 + 方法暴露来实现「对外不可变」。

**实现方法：**

1. 定义备忘录结构体（如 `Memento`），字段不导出，只暴露必要的读取方法。
2. 发起者实现 `Save()`：把当前内部状态拷贝进一个新快照并返回。
3. 发起者实现 `Restore(m)`：用快照里的值覆盖当前状态。
4. 负责人（如 `History`）用切片或栈保存快照，提供 `Push`/`Pop`，实现撤销栈。

**是否使用：**

- 适用场景：需要撤销/重做（编辑器、绘图工具）、游戏存档、事务回滚、需要保留对象历史快照的场景。
- 判断标准：当对象状态需要「回退到过去某个点」，且不能靠外部直接读写字段来实现时，用备忘录模式。
- 需要警惕：快照会占用内存，状态量大或快照频繁时会变重；可以用增量快照、只存差异来优化。

**Go 落地要点：**

- 备忘录的字段用非导出字段，避免外部随意篡改快照，保持封装。
- `Save()` 必须做值拷贝（深拷贝），如果状态里含 slice/map/指针，直接赋值会共享底层数据，后续修改会污染快照。
- 负责人只做存取，不解析快照内容，职责单一。
- 撤销栈用 slice 模拟即可，`append` 入栈、切掉末尾出栈，简单且够用。

**相关模式：**

- 命令模式：命令模式常配合备忘录实现「可撤销的命令」，每条命令保存执行前的快照。
- 原型模式：两者都涉及状态复制，原型是复制出可用的新对象，备忘录只是保存状态快照。
