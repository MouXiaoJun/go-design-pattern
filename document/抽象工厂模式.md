# 抽象工厂模式 Abstract Factory Design Pattern

**分类：** 创建型模式——提供一个接口，用于创建一组相关或相互依赖的对象（对象族），而无需指定它们的具体类。

## 定义

解决的问题：需要创建的对象不是一个，而是一组必须"搭配使用"的关联对象。例如暗色主题下的按钮和文本框必须同属暗色风格，不能混入浅色组件。若逐个 `new` 具体类，调用方会与具体实现强耦合，换一套产品族就要改多处代码。

Go 中的落地：用一个抽象工厂接口声明一组创建方法，每个具体工厂实现整个对象族的创建。客户端只依赖抽象工厂接口，切换主题等于换一个工厂实例，其余代码不动。

- 抽象产品接口：`Button`、`Text`，定义一族组件各自的统一能力
- 抽象工厂接口：`ThemeFactory`，声明 `CreateButton`、`CreateText`
- 具体工厂：`DarkThemeFactory`、`LightThemeFactory`，各自产出风格一致的一族产品

## 实现方法

1. 先定义一族产品的抽象接口（如 `Button`、`Text`）
2. 定义抽象工厂接口，为族内每种产品声明一个创建方法
3. 为每个"产品族"实现一个具体工厂，返回同族的具体产品
4. 客户端通过抽象工厂接口使用，不直接依赖具体工厂

## 是否使用

- 系统要创建一组必须彼此搭配、不能混用的对象族
- 产品族会整体切换（如换主题、换数据库驱动），且不希望改动调用方
- 需要强制"一族产品同进同出"，避免调用方自行组合出错误搭配

判断标准：如果每次只创建单个对象，用简单工厂或工厂方法即可，不必上抽象工厂；只有"成组创建"是刚需时才值得引入。

## Go 落地要点

- 抽象工厂在 Go 里就是"返回接口的接口"：工厂接口的每个方法返回产品接口
- 具体工厂用空结构体实现即可，无需状态；返回具体产品时直接返回其接口类型
- 可配合 `switch` 或注册表按名称选择工厂，但核心是让调用方拿到 `ThemeFactory` 接口而非具体工厂

## 相关模式

- 工厂方法：抽象工厂里的每个创建方法本质上可看作一个工厂方法
- 单例模式：具体工厂常常只需要一个实例
